Track shared, non-sensitive project choices in `.fluxzero/dev.yaml`; keep generated session state under
`.fluxzero/dev/` ignored. Inspect an existing configuration before editing and preserve its intent.

## Use the installed configuration reference

Run `fz dev config` before creating or changing `.fluxzero/dev.yaml`. It prints the full configuration reference
aligned with the dev-server version selected for this project. Use `fz --help` and `fz dev --help` for current
commands, lifecycle options and defaults. These tools release independently of the SDK, so their current output
owns supported YAML keys, option precedence and secret-reference syntax.

The configuration expresses stable project choices such as selected applications, namespaces, environments,
frontend processes and routing, identity-provider integration, and startup commands. Use the reference to determine
which choices the selected version supports and how to express them. Do not copy a schema or infer flags from
another project, an older SDK manual or memory.

For a managed frontend, configure its working directory, dependency setup and development command using that
reference. Let the dev server allocate its internal port and configure backend routes to reach Fluxzero rather than
the frontend. Keep those commands deterministic and watch the resulting frontend state through the project MCP.

Do not store resolved secrets in this file, logs or agent output. Follow the supported secret-reference mechanism
without resolving or printing secret values.

## Build integration

The Maven and Gradle plugins provide project-local `fluxzero:dev` and `fluxzeroDev` launchers. The Gradle plugin also
provides `fluxzeroDevMetadata` and `fluxzeroDevTest`, which supply the compile/classpath and selected-test contract
used by the dev server. Keep the integration generated by the CLI; apply the Gradle plugin at the root so multi-project
applications are discovered together. Use the installed agent plugin's `fluxzero-dev` MCP connection for the ordinary
edit/build/test loop, without launching a second environment alongside it.
