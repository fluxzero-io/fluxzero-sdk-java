**Your agent builds the product. Fluxzero runs it.** The local tools give you and your agent a working environment and evidence. Cloud delivery makes a checked version available to users.

## From an instruction to a working app

<GuideFlow label="One shared development environment" stages={[
  { title: "Your agent", description: "The plugin and MCP supply guidance and project tools." },
  { title: "Dev Server", description: "One environment manages apps, builds, tests and services." },
  { title: "Devboard", description: "You see the preview and the same development feedback." },
]} />

The **agent plugin** gives your coding agent the Fluxzero workflow. Its **MCP connection** retrieves SDK guidance matched to the project and exposes development tools. The **CLI** creates projects and launches or manages their environment.

The **Dev Server** manages backend and frontend processes, local services, builds, affected tests and startup actions. **Devboard** is your browser view of that work: the app, tested scenarios, recorded progress and monitoring.

The **SDK** supplies the programming model used by application code. Developers can work directly in the same code; using an agent does not create a separate kind of application.

## From a checked change to a live product

<GuideFlow label="Deliver the same product to users" stages={[
  { title: "Build tooling", description: "Package the application and publish its image." },
  { title: "Delivery workflow", description: "Request deployment through the Deploy Action or System API." },
  { title: "Cloud dashboard", description: "See the version, tasks, configuration and runtime evidence." },

A GitHub workflow authenticates to Fluxzero before requesting deployment. The dashboard lets you and your agent inspect the result and the product’s behavior after release.

Your local project and live application have separate data and configuration. The plugin does not automatically grant production access. Identity for app users is also separate from the permissions used by a deployment workflow.

Use [Tools & automation](/docs/tools/overview) for installation and reference, [Local and live environments](/docs/building/environments) for the boundaries, and [Publishing your app](/docs/tutorials/cloud-deployment) for the release procedure.
