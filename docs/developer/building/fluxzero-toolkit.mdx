**Fluxzero is the cloud that runs your product.** It hosts your frontend and backend and brings data, messaging,
security, recovery, and observability together. You and your agent use the tools below to build for that cloud,
try the complete application locally, and publish it when it is ready.

<Card title="Your product runs on Fluxzero" icon="rocket">
Publish your checked application from GitHub. Fluxzero runs it for your users, stores its data, routes requests,
and records what happens. You manage the product through the [Fluxzero dashboard](https://dashboard.fluxzero.io).
The [publishing guide](/docs/tutorials/cloud-deployment) takes you through the steps.
</Card>

## Tools for building your app

<CardGrid>
  <Card title="Agent plugins" icon="pencil">

  <Card title="SDK" icon="document">

  <Card title="CLI" icon="laptop">

  </Card>
  <Card title="Dev Server and Devboard" icon="laptop">

[Local development](/docs/building/local-development) · [Repository](https://github.com/fluxzero-io/fluxzero-dev-server)
  </Card>

## Identity for your users

Fluxzero's **identity provider (IDP)** supplies sign-in so your application can recognize people. You define what each
person may see or do; the application enforces those rules using the SDK. The local development environment supports
trying sign-in flows before you publish. Developers can find the details in the
[authentication guide](/docs/guides/messaging/role-based-access-control).

<Aside type="tip" title="One route from idea to live product">
Describe a feature → build and test locally → try it in Devboard → publish on Fluxzero.
You can follow that route on your own or with a team. Developers can work directly in the same codebase at any point.
</Aside>
