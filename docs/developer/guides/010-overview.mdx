<span id="developer-guides"></span>

Build your application's behavior in Java or Kotlin: send an action, handle it, remember the result and react to what
happened. Fluxzero provides message delivery, persistence and testing around that code.

Start with [Core concepts](/docs/getting-started/core-concepts) for a small complete example, or add your first
[HTTP endpoint](/docs/getting-started/hello-world). The [to-do tutorial](/docs/tutorials/first-app) then grows an
application one feature at a time.

## Build one feature

- [Prevent double bookings](/docs/guides/modeling-and-persistence/preventing-double-bookings).
- [Wait for a response](/docs/guides/modeling-and-persistence/waiting-for-a-response).
- [Keep a screen up to date](/docs/guides/messaging/updating-a-live-screen).
- [React to a state change](/docs/guides/modeling-and-persistence/reacting-to-a-change).
- [Build an API integration](/docs/guides/messaging/building-api-integrations) and [receive its callbacks](/docs/guides/messaging/receiving-webhooks).
- [Use PII and erase it](/docs/guides/data-control-and-serialization/using-and-erasing-pii).

## Evolve a running application

- [Build a feature from past events](/docs/guides/messaging/adding-a-feature-to-history).
- [Correct historical results alongside live processing](/docs/guides/messaging/live-and-historical-processing).

## Messaging

Messages let one part of your application ask another to do work without choosing which process handles it.

- [Send an action or query](/docs/guides/messaging/sending-messages), then [write its handler](/docs/guides/messaging/message-handling).
- [Test the behavior locally](/docs/guides/messaging/testing-your-handlers).
- [Expose an HTTP endpoint](/docs/guides/messaging/handling-web-requests) or [build an API integration](/docs/guides/messaging/building-api-integrations).
- [Schedule work for later](/docs/guides/messaging/message-scheduling).

When you need independent background processing, continue with [consumers and tracking](/docs/guides/messaging/message-tracking),
[replays](/docs/guides/messaging/message-replays) and [metrics](/docs/guides/messaging/metrics-messages).

## Modeling & Persistence

Models remember the things your users work with: tasks, orders or bookings. Commands express how they change.

- [Design the Model's state](/docs/guides/modeling-and-persistence/model-state) and [apply changes](/docs/guides/modeling-and-persistence/updating-entities).
- [Connect related Models](/docs/guides/modeling-and-persistence/nested-entities).
- [Load or search their state](/docs/guides/modeling-and-persistence/model-query-guide).

Then choose [storage behavior](/docs/guides/modeling-and-persistence/model-persistence), explore
[historical Graphs](/docs/guides/modeling-and-persistence/temporal-graphs), or coordinate long-running work with
[stateful handlers](/docs/guides/modeling-and-persistence/stateful-handlers).

## Data Control & Serialization

As the application grows, its stored data outlives individual versions of the code. Learn to
[evolve old data](/docs/guides/data-control-and-serialization/upcasting-and-downcasting),
[protect sensitive fields](/docs/guides/data-control-and-serialization/protecting-sensitive-data) and
[filter responses for their audience](/docs/guides/data-control-and-serialization/user-based-content-filtering).

## Configuration & Support

Use [application properties](/docs/guides/configuration/application-properties) for environment-specific settings
and [the Fluxzero builder](/docs/guides/configuration/configuring-fluxzero) to register handlers or customize the SDK.
The sidebar contains focused guides for extension points and operational concerns.

Existing 1.x application? The [2.0 overview](/docs/fluxzero-2) explains the Model/Graph design;
the [migration guide](/docs/fluxzero-2-deep-dive#upgrading-from-1x) explains the transition.
